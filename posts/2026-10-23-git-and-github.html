아이펠에서 Git과 GitHub를 처음 배운 날

아이펠GitGitHub

오늘 모두의연구소 아이펠 수업에서 Git과 GitHub를 배웠다. 솔직히 이름만 들어봤지 제대로 써본 적은 없었는데, 막상 해보니 생각보다 훨씬 재미있었다.

오늘 수업, 정말 재미있었다! 배운 걸 바로 써먹어서 이 블로그까지 만들었다.

Git과 GitHub는 뭐가 다를까

처음에는 둘이 같은 건 줄 알았는데, 역할이 달랐다.

GitGitHub
내 컴퓨터에서 파일의 변경 이력을 관리하는 도구 Git 저장소를 인터넷에 올려두고 공유하는 서비스

Git으로 내 작업을 차곡차곡 저장(커밋)하고, GitHub에 올려서(푸시) 어디서든 보고 다른 사람과 함께 쓸 수 있게 하는 구조다.

오늘 직접 해본 것

빈 폴더 하나에서 시작해서 GitHub 저장소와 연결하고 첫 커밋을 올렸다.

# 1. 폴더를 Git 저장소로 만들기
git init -b main

# 2. GitHub 저장소와 연결하기
git remote add origin https://github.com/jsseo0420/my-blog.git

# 3. 누가 커밋했는지 알려주기
git config --global user.name "jsseo0420"
git config --global user.email "..."

# 4. 파일을 담고, 저장하고, 올리기
git add README.md
git commit -m "Initial commit"
git push -u origin main

명령어마다 하는 일을 정리해보면 이렇다.

  • git init: 이 폴더의 변경 이력을 Git이 관리하기 시작한다.
  • git remote add: 내 폴더와 GitHub 저장소를 이어준다.
  • git add: 저장할 파일을 고른다.
  • git commit: 고른 파일을 하나의 기록으로 남긴다.
  • git push: 남긴 기록을 GitHub로 보낸다.

작은 실수에서 배운 것

git config --global user.name "이름"을 예시 그대로 입력하는 바람에 내 이름이 진짜로 "이름"이 될 뻔했다. 😅 커밋에는 작성자가 함께 기록되니까, 처음에 이름과 이메일을 제대로 설정해 두는 게 중요하다는 걸 알게 됐다.

그리고 이 블로그
